# ADR-0007: Spring Boot's GitHub issues as the dataset

- **Status:** Accepted
- **Date:** 2026-11-26

## Context

To measure accuracy honestly we need real issues with trustworthy labels, available through a live API so the integration is real.

Counts from the GitHub search API on 2026-11-26 (`repo:spring-projects/spring-boot is:issue`):

| Label | Issues |
|---|---|
| `type: bug` | 4,789 |
| `type: enhancement` | 4,336 |
| `type: documentation` | 3,131 |
| `status: invalid` | 4,696 |
| `status: declined` | 2,063 |
| `status: duplicate` | 2,012 |
| `for: stackoverflow` | 1,744 |
| `type: task` | 7,060 (mostly internal, excluded) |
| `type: dependency-upgrade` | 10,507 (bot-generated, excluded) |

The repository also has `type: regression`, `status: waiting-for-feedback` and several `theme: …` labels (for example `theme: observability`, `theme: containers`).

## Decision

Use **[spring-projects/spring-boot](https://github.com/spring-projects/spring-boot)** issues as the primary dataset, with label mapping and exclusions as defined in [DESIGN §8.1](../DESIGN.md).

## Alternatives considered

| Option | Pros | Cons |
|---|---|---|
| Synthetic tickets generated by an LLM | Unlimited and clean | No real ground truth; evaluating LLM output on LLM-made data is circular |
| Kaggle support-ticket datasets | Ready to use | Static files, no live API integration, often unclear licences |
| microsoft/vscode issues | Huge volume | Very noisy labels; not Java-related |
| spring-projects/spring-framework | Same conventions | Smaller; a good *secondary* repo for the multi-repo stretch goal |

## Consequences

- The domain is Java-relevant, which makes a nice detail in interviews.
- We must filter out the large amount of bot and administrative noise (dependency upgrades, forward and back ports, tasks).
- Duplicate references often point to pull requests or external projects, so fewer pairs are usable ([DESIGN §9](../DESIGN.md)).
- We must respect GitHub rate limits and terms. Eval datasets store **issue numbers and labels only**; text is loaded from our own database after import.
